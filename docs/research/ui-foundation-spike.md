## 0. Correction: there is no `ui/common` at the pinned SHA

The plan's `ui/common` path does not exist (directory listing of `ui/` confirms:
packages are `analyse`, `bits`, …, `lib`, `puzzle`, `round`, `site`, …, no
`common`). The shared theme lives in **`ui/lib/css/`**:

- Shared entry: `ui/lib/css/_plugin.scss` — contains exactly one line,
  `@import 'abstract/all';` (tokens, mixins, breakpoints). Every module build
  stylesheet imports it first.
- Module build entry (puzzle): `ui/puzzle/css/build/puzzle.scss` — imports
  shared partials first, then local styles via `@import '../puzzle';`
  (`ui/puzzle/css/_puzzle.scss` re-exports `layout`, `side`, `tools`,
  `after`, `session`, `zen`).
- So the adoption shape is: **one shared token/mixin layer + per-screen local
  SCSS that imports shared component partials then adds screen styles** —
  directly mappable onto our single `apps/web/src/app.css`
  (shared tokens/components at top, per-screen sections below).

## 1. Our current baseline (local reads)

- Rendering model (`apps/web/src/*-view.ts`): template-string `innerHTML` +
  `querySelector` ref caching (`this.el.*`, `queryRefs()`), then surgical DOM
  updates and manual event binding (`bindEvents()`). State lives in private
  view fields (`game`, `timer`, `revealed`, `message`, `renamingId`, …).
- Lifecycle (`apps/web/src/router.ts`): `Screen { id, mount(host), unmount() }`.
  Router owns mount/teardown; `mount` builds DOM + listeners, `unmount`
  nulls host, removes document/window listeners, destroys the chessground
  instance (Train). `screens.ts` is only a factory registry.
- Simplest screen (`apps/web/src/history-view.ts`): pure snapshot
  (`summarizeHistory` over read-only service getters) rendered once in
  `mount`; no listeners, no updates, no board. Ideal vnode pilot shape.
- i18n (`apps/web/src/i18n.ts`): flat `Record<string,string>` dict,
  `t(key, params)` with `{param}` interpolation, `data-i18n` attributes.
  Lila uses generated `window.i18n` catalogs + lazy `requiresI18n` loading —
  **do not adopt**; keep our dict, it already covers all five screens.

## 3. The Lichess ctrl/view/redraw pattern (precise)

- **Where state lives**: one controller class per screen
  (`ui/puzzle/src/ctrl.ts`: `export default class PuzzleCtrl` — `data`,
  `tree`, `path/node/mainline`, `mode: 'play'|'view'|'try'`, `lastFeedback`,
  toggles, `cgVersion`, …). Views hold no state; they are pure functions
  `(ctrl) => VNode`, split per subtree: `view/main.ts` (layout shell),
  `view/chessground.ts`, `view/tree.ts`, `view/feedback.ts`, `view/side.ts`
  (+ `after.ts`, `boardMenu.ts`, `theme.ts`, `nvuiView.ts` — verified via
  `src/view/` listing).
- **What triggers redraw**: `redraw` is a closure created once in the
  bootstrap and injected into the controller constructor
  (`new PuzzleCtrl(opts, redraw)`). Every mutation path calls it:
  `addNode`, `jump` (via callers), `sendResult().then(redraw)`,
  `setTimeout(..., redraw)` (revert/setup/hint delays), pubsub/visibility
  handlers, `bind('click', handler, redraw)` / `bind('change', …, redraw)`
  in vnode hooks, `storedBooleanPropWithEffect(..., this.redraw)`.
  Nothing observes; every writer calls `redraw()` explicitly.
- **Mount/redraw mechanics** (`ui/puzzle/src/puzzle.ts`, Snabbdom 3.5.1,
  `init([classModule, attributesModule])`): `initModule` awaits
  `site.asset.loadPieces`, `querySelector('main.puzzle')`, builds ctrl,
  `patch(element, render())` once, then `redraw = () =>
  patch(vnode, render())` reassigns the vnode ref each patch.
- **How the board avoids remount**: `view/chessground.ts` returns a bare
  `div.cg-wrap.cgv{cgVersion}` whose `hook: { ...onInsert(el =>
  ctrl.setChessground(makeChessground(el, makeConfig(ctrl)))), destroy: …
  }`. Snabbdom's diff keeps the same element across patches (same selector
  → `insert` hook fires once, never re-runs); all subsequent board changes
  go through the imperative `CgApi` (`g.set(...)`, `showGround`) inside
  controller methods, never through vnode props. Forced remount happens
  only by changing the selector (`cgVersion++` on flip). `destroy` hook
  disposes the ground on subtree removal.
- **View helpers** (`ui/lib/src/view/`, barrel `index.ts`): `hl(sel,
  dataOrKids?, kids?)` (`snabbdom.ts`) — tolerant `h()` wrapper filtering
  falsy kids and flattening arrays so views can inline conditionals;
  `onInsert`, `bind`/`bindNonPassive`/`bindSubmit` (listener + optional
  redraw), `dataIcon`, `MaybeVNode`; tag factories (`snabbdomElements.ts`);
  widget-level `cmnToggle/cmnToggleWrap` (`view/cmn-toggle.ts`).

## 6. Proposed seam for our codebase

- **Keep the `Screen` shell untouched**: `router.ts` (`registerScreen`,
  `parseHash`, `startRouter`, mount/unmount ownership), `ScreenId`, and
  per-screen `mount(host)/unmount()` signatures stay exactly as-is.
- **Per-screen ctrl + subtree redraw inside `mount`**: each view file gains
  a small `*Ctrl` class holding the mutable state currently in private
  view fields; `mount` does `patch(host.firstChild-or-wrapper, view(ctrl))`
  once and passes a `redraw = () => patch(vnode, view(ctrl))` closure into
  the ctrl. All existing mutation sites call `redraw()` instead of
  surgical DOM writes. Pure `summarize*`-style projections
  (History already has one) become the view input.
- **Board element outside the patched tree**: Train keeps owning its
  `Chessground` instance exactly as today. The board host `div` is created
  in `mount` (or via an `insert`-hook vnode with a stable selector, Lila
  `chessground.ts` shape) and is **never part of the diffed children** —
  controller methods call `ground.set(...)` imperatively. Unmount destroys
  the ground and drops the vnode ref, mirroring today's teardown.
- **CSS**: keep single `app.css`; add a tokens block shaped like §2
  (clean-room values) + adopt class additions per screen per §4. No SCSS
  toolchain, no generated wrappers.

## 7. Pilot recommendation: History, not Collections

**Pilot = History.** Reasons: strictly read-only (no writer to miss a
`redraw()` call); single synchronous render from an existing pure snapshot
(`summarizeHistory` ≈ Lila's `data → view(ctrl)` input); no board, no
timers, no forms, no listeners — zero remount hazard, so S1 proves the
theme + ctrl/view/redraw seam in isolation. Collections is the correct
*second* screen (adds `message`/`renamingId` local state → redraw on
create/rename/delete/add/remove, plus `.box`/form rows), but its
interleaved re-renders would tangle pilot evaluation. Train comes last —
see §8.

## 8. Risks

1. **Train board-binding remount hazard (heads the list).** If the board
   host div ever becomes a normally-diffed vnode child, any patch that
   changes its selector/position recreates the element and kills the live
   chessground instance (piece sprites, drag state, pending premove).
   Lila avoids this via insert-once hook + imperative updates + selector
   change only on flip (`cgVersion`). S6 must prove: rapid redraws during
   play (move → reply → feedback → clock) never remount the board element
   (assert element identity across N redraws + promotion + flip + visibility
   resume), and unmount reliably destroys it.
2. **Redraw completeness**: every surgical-update site must gain a
   `redraw()` call; a missed writer shows stale UI with no error. Audit by
   diffing writer lists per screen (Train has the most: moves, replies,
   timers, reveal, skip, review nav, queue/progress).
3. **Timer/async redraw-after-unmount**: Lila's `setTimeout(..., redraw)`
   and reply timers can fire post-teardown; our `unmount` must guard or
   cancel them (Train `AttemptTimer`, delayed view-solution/canViewSolution
   equivalents).
4. **SCSS closure entanglement**: shared partials assume `$c-*`/mixin
   globals from `ui/build`-generated wrappers; selective copying without
   the toolchain silently breaks. Hence clean-room re-expression (§5).
5. **i18n mismatch**: `requiresI18n`-style lazy catalogs don't fit our
   sync dict; ported views must use `t()` directly.
6. **Plan-path drift**: UI-001's `ui/common` reference is stale (see §0);
   update the plan to point at `ui/lib/css/` + `ui/lib/src/view/` + the
   pinned SHA or S1 will 404.
